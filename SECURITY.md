# Политика безопасности

## Как сообщить об уязвимости

Приватно, через GitHub: вкладка **Security** → **Report a vulnerability**
(`https://github.com/lukavtz/byte-guardian/security/advisories/new`).

Публичные issue, pull request и обсуждения для уязвимостей не используйте:
они видны всем до исправления.

В отчёте укажите: версию или SHA, режим (`polling` / `webhook`), шаги
воспроизведения, влияние. Не прикладывайте рабочие токены и пароли —
достаточно описания, что именно раскрывается.

Ответ — в течение 7 дней. Публичное раскрытие — только после того, как фикс
попал в `main` и релиз выпущен.

## Что входит в область

| Область | Ожидание |
|---|---|
| `BOT_TOKEN` | Не попадает в логи, ответы бота и репозиторий. Утечка = немедленный `revoke` в @BotFather. |
| `WEBHOOK_SECRET` | Telegram присылает его в `secret_token`; запрос без верного заголовка отклоняется. |
| `ADMIN_IDS` | `/admin` и `/broadcast` доступны только этим ID. Пустой список = все админ-команды запрещены. |
| Логи LLM | В логи идут только статус, задержка и число токенов. Вопросы пользователей и ответы модели не логируются. |
| Персональные данные | Бот не хранит переписку; в Postgres только user id, язык и подписка на рассылки. |
| Контент | Неверная инструкция при ЧС — дефект безопасности. Отдельно: бот не ставит диагнозы и дозировки. |

## Что не входит

- Уязвимости в Telegram, aiogram, Postgres, Redis, Podman и LLM-провайдере —
  сообщайте их мейнтейнерам.
- Отсутствие rate limiting на публичном инстансе, если это не даёт обхода
  админ-проверок или доступа к данным.
- Социнженерия против мейнтейнера.

## Зависимости

`uv lock --check` и `uv sync --frozen` в CI фиксируют граф пакетов. Обновления
зависимостей — отдельным pull request с прогоном тестов.

## Секреты в репозитории

`.env` в `.gitignore`; в репозитории только `.env.example` без значений.
Если секрет всё же попал в коммит — сначала отзовите его у провайдера,
потом чистите историю: удаление файла коммитом не отменяет утечку.
